# Local Windows test report — 2026-09-13

## Environment and scope

- Windows build 26100, release 24H2 (registry ProductName reports Windows 10 IoT
  Enterprise LTSC 2024; that string is recorded without inferring a different build).
- Windows PowerShell 5.1; application version string 3.0.
- Two detected 1920 x 1080 displays, each with an 1870 x 1080 working area.
- Synthetic images only; no personal photographs used.
- No HEIF/HEVC/AV1 Appx packages were returned by the installed-package inventory.

## Installation and removal — passed

`Test-InstallCycle.ps1 -Tours 5` completed five real installation/removal cycles.
Each installed state had 22 file associations, four executables, ten language
files, the directory action, uninstall registration and Start menu shortcut.
Each removal left none of those Jipeg items behind. The classic-menu option was
not enabled; Explorer was not intentionally restarted by these tests.

`Test-Release.ps1` installed the locally built ZIP and converted its fixture from
16,531 bytes to 11,062 bytes. All archive checks passed. This did not test the
one-line network bootstrapper or publish a release.

`Test-UninstallWait.ps1` held the conversion lock while uninstalling. The menu
was removed but application files remained. After releasing the lock, the folder
was removed within the 15-second deadline. The working copy was then reinstalled.
This checks the lock protocol with a synthetic held lock, not a running image batch.

Fixes made before running the removal tests:

- Load shared language/settings helpers in the uninstaller before using them.
- Use a separate PowerShell cleanup worker with literal, validated paths instead
  of constructing a cmd deletion script. Refuse reparse points and leave files
  intact if a conversion still holds its lock at the deadline.
- Return a failing exit code from the cycle harness when discrepancies occur.

## Window geometry — defect found and fixed

The settings client area is 798 design units high, but the common scaling cap
still assumed 760. At a simulated 150%, the window measured 749 x 1123 pixels
and did not fit either screen. Updating the design height to 798 fixes this case.

| Requested scale | Effective scale | Window size after fix | Fits both work areas |
|---|---|---|---|
| 100% | 1.000 | 556 x 837 | Yes |
| 125% | 1.250 | 691 x 1037 | Yes |
| 150% | 1.293 | 714 x 1071 | Yes |

The real settings controls were constructed and measured by `Test-WindowLayout.ps1`.
No child-control bounds overflow was found. The 150% regression is included in CI.
These are geometric measurements using the detected work areas, **not** a visual
inspection or a test of dragging between screens with different physical DPI.
The UI automation tool did not expose the Jipeg windows launched by the test
commands, so no screenshot-based approval is claimed. Scaling still uses the
primary display; physical mixed-DPI behavior remains unverified.

## HEIC and AVIF — successful decoding blocked

`build-device-fixtures.py` generated 800 x 600 HEIC and AVIF images and successfully
decoded both using Pillow 12.3.0 / pillow-heif 1.7.0, independently of Windows WIC.

| Fixture | Bytes | SHA-256 |
|---|---:|---|
| sample.heic | 106218 | `29ce080a720aa081db72ff181238f270312aed317a59080dd94eefd6be173a29` |
| sample.avif | 23433 | `cd633d90eecc77b7546c015ae789b1877570ee01ba711ae90c47b57c462df4e9` |

`Test-DeviceCodecs.ps1` passed these valid files to the actual Jipeg WIC decoder.
Both were refused with the missing-codec messages. The script exits 2 to report
that the successful-decode test is blocked, rather than marking this as a pass.
No Store codecs were purchased or installed. Installing Python fixture libraries
does not add Windows WIC codecs and cannot validate Jipeg's Windows decoder.

Successful decoding, orientation/colour checks and end-to-end HEIC/AVIF conversion
must be rerun on a machine with the relevant Windows codecs installed.
